{# ========================================================================== THE THREAD PANE — static chrome only. Every *variable* part of a thread is rendered by cartflow-messages.js from `GET /api/messages/threads/{username}`: the header, the bubbles, the request banner's wording, the composer's disabled reason. This file holds the parts that never change — the boxes those things go into, and the states that carry no data (the desktop placeholder, the load-earlier button, the typing line). Why the split is here and not somewhere more even: a bubble has to be drawn by JavaScript no matter what, because it can arrive over a socket. Drawing it in Jinja *as well* would mean two renderers for one row, and the day they disagree is the day the same message reads differently depending on whether you scrolled to it or watched it land. So there is exactly one renderer for anything with a message in it, and it lives in JS. Jinja owns the furniture. The DOM contract with cartflow-messages.js is the `data-*` attributes below. They are the API between the two files; classes are styling and may change. Included by messages.html into the right-hand pane. Nothing here is conditional on the viewer, so it takes no context. ========================================================================== #} {# ---- Desktop placeholder. Only ever visible at lg+, where the pane exists with nothing open. On a phone the list and the thread are the same column, so "no thread selected" is just the list, and this is never shown. ---- #}
